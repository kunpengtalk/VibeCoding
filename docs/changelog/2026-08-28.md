## 一、迁移整合：KunpengFactory → VibeCoding 双向对齐

### 1.1 内测准入体系（可开关，默认关闭）

原先 KunpengFactory 有完整的内测邀请码体系，VibeCoding 缺这套能力。
本次完整迁移，但**默认关闭**（`beta_apply_enabled = false`），保持现有开放注册不变。

| 层 | 内容 |
|---|---|
| 模型 | `InviteCode`、`BetaApplication` |
| DAO | `database/dao/invite_code.py`（生成 `VB-XXXXXXXX`、校验、原子消费） |
| 接口 | `api/v1/beta.py`（`/apply` 提交申请、`/status` 查状态、`/config` 查开关） |
| 配置 | `SystemConfig` 新增 `beta_apply_enabled` 等 4 字段 |
| 邮件 | `send_invite_code_email()`（邀请码邮件） |
| Admin | 邀请码管理（生成/列表/作废）+ 内测审核（approve 自动发码/reject） |
| 前端 | `BetaApply.vue` + `betaApi/BetaApply` 模块，登录注册页按开关展示入口 |

**注册门控接入 4 条路径**，含 `email-login`/`sms-login` 的「登录即注册」分支
（这是绕过点，源项目未覆盖）。

**流程**：用户申请 → 管理员审核通过自动发码 → 用户注册时填写 → 消费后绑定使用者。
邀请码不发积分，仅作准入凭证。

## 三、源码交付审核状态机（本次新增功能）

### 问题

存在两套状态，C 端页面只用了其中一套：

| 状态 | 视角 | 字段 | 页面是否使用 |
|---|---|---|---|
| GitHub 邀请进度 | 技术 | `repo_invite_status`（7 态） | ✅ 用了 |
| **交付审核进度** | **业务/客服** | **`delivery_status`（3 态）** | ❌ **没用** |

导致用户提交后：界面无变化、表单始终可编辑可重复提交、没有「已提交成功 / 审核已通过」展示。

### 修复

以 `delivery_status` 驱动页面：

| 状态 | 用户看到 | 表单 |
|---|---|---|
| `pending_info` | 填写信息 | 可编辑 |
| `pending_delivery` | **已提交，客服将尽快添加** | **锁定**（需点「修改信息」才解锁） |
| `delivered` | **审核已通过** | 锁定，展示 `git clone` |

标题栏增加状态徽章（已提交待审核 / 审核已通过），步骤条第 3 步改为「客服添加权限」。

### 连带修复

用户**更换 GitHub 账号**时，因 `derive_delivery_status` 中 `delivered` 优先级最高，
状态不会回退 → 客服不会给新账号重新开权限。
现改为账号变更时重置为 `pending_delivery` 重新审核。

## 四、部署中存在风险的操作（已规避）

### 4.1 积分唯一索引会误删正常消费记录 ⚠️

建索引前发现「重复」数据并非 bug，而是**正常的分步消费**：

| 项目 | 条数 | 金额 | 跨度 |
|---|---|---|---|
| `article_project` | 7 条 | -5,-2,-3,-3,-2,-2,-3 | 35 秒 |
| `video_project` | 6 条 | -23,-1,-1,-29,-2,-1 | 3 小时 |

按原方案执行将删除 12 条正常记录，且 Analytics 已改为查此表，统计口径会失真。

**改为 partial index，仅约束充值**：
```sql
CREATE UNIQUE INDEX uq_point_txn_recharge
  ON point_transactions (user_id, source_type, source_id)
  WHERE type = 'recharge';
```
充值仍防重复到账，消费完全不受约束。

### 4.2 生产库 `beta_apply_enabled` 为 `true`

该字段生产早已存在且为 `true`，VibeBase 之前不读所以无影响，本次开始生效
—— 不处理将阻断所有新注册。已显式置为 `false`。

### 4.3 依赖版本不存在导致构建失败

`courlan==1.4.3` 在镜像上不存在（最高 1.4.0）。
改为**只锁定 `trafilatura==2.1.0`，子依赖交给 pip 自动解析**。

### 4.4 生产配置保护

`docker-compose.yml` 中生产为 `MAIL_USERNAME=postmaster@vibeadmin.cn`，
本地为 `support@vibeadmin.cn`。同步时**刻意排除**该文件，保住生产配置。
